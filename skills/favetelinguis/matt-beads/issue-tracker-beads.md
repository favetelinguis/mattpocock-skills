# Issue tracker: Beads (external workspace)

Issues and specs for this repo live in an external [Beads](https://github.com/gastownhall/beads) workspace at `<ws>`. Use `bd -C <ws>` for all operations so no `.beads/`, `.beads.gate.lock`, or config files are ever created inside the repository.

## Conventions

- **Create an issue**: `bd -C <ws> create "<title>" -t <type> -d "..."`. Pass `--body-file - <<'EOF'` for multi-line bodies, and `--silent` when scripting to output only the new `<id>`. Types via `-t`: `task` (default), `bug`, `feature` (alias `enhancement`), `epic`, `chore`, `decision`, `spike`, `story`, `milestone`. Priority via `-p` (`0` to `4`, `0` highest, default `2`).
- **Read an issue**: `bd -C <ws> show <id>` for human-readable output (includes description, labels, parent, blocking edges, and comments). For JSON output, always include `--include-comments`: `bd -C <ws> show <id> --include-comments --json` (`bd show --json` without `--include-comments` omits all comments).
- **List issues**: `bd -C <ws> list --flat --json` with `--status`, `--label` (`-l`), `--label-any`, `--exclude-label`, `--no-labels`, `--type` (`-t`), `--assignee` (`-a`), and `--parent` filters. Always comma-separate multiple statuses (`--status open,in_progress,blocked,deferred`); repeating `-s` overwrites earlier values.
- **Find ready work**: `bd -C <ws> ready -l ready-for-agent --json` lists `open` issues carrying `ready-for-agent` with no open blockers (`bd ready` excludes `in_progress`, `blocked`, `deferred`, `pinned`, `hooked`, and `closed`). `bd -C <ws> blocked --json` lists dependency-blocked issues and their open blocker ids.
- **Make an issue a child of a parent**: `bd -C <ws> create "<title>" --parent <parent-id> --no-inherit-labels ...`, or `bd -C <ws> update <child-id> --parent <parent-id>` afterwards. Always pass `--no-inherit-labels` on `bd create --parent` so child issues do not inherit `wayfinder:map` or parent triage labels. List all children (including closed) with `bd -C <ws> children <parent-id> --json`.
- **Blocking**: Beads's **native issue dependencies**, the canonical representation. Add an edge at creation with `bd -C <ws> create ... --deps blocked-by:<blocker-id>` (comma-separate multiple `blocked-by:<id>` entries) or afterwards with `bd -C <ws> dep add <blocked-id> <blocker-id>` (first argument depends on second argument). `bd -C <ws> dep tree <id>` renders the dependency graph. A ticket is unblocked when every blocker is closed.
- **Count open blockers**: `bd -C <ws> show <id> --json | jq '[.[0].dependencies[]? | select(.dependency_type == "blocks" and .status != "closed")] | length'` (`0` means startable).
- **Comment on an issue**: `bd -C <ws> comments add <id> "..."` or `bd -C <ws> comments add <id> -f <file>`. List comments with `bd -C <ws> comments <id> --json`.
- **Apply / remove labels and update fields**: `bd -C <ws> update <id> -t <type> -s <status> --remove-label <old-label> --add-label <new-label>`. Never pass the same label to both `--add-label` and `--remove-label` in one `bd update` call (`--remove-label` runs after `--add-label`). Never run `bd edit`, which opens an interactive `$EDITOR`; always use `bd update` flags.
- **Claim**: `bd -C <ws> update <id> --claim` (atomically assigns you and sets `in_progress`). Release an abandoned claim with `bd -C <ws> unclaim <id>`.
- **Close**: post the explanation with `bd -C <ws> comments add <id> "..."` when a detailed closing comment is needed, then `bd -C <ws> close <id> --reason "..."`. When closing an issue that still has open blockers or open children (such as a `wontfix` or out-of-scope ticket), pass `--force`: `bd -C <ws> close <id> --force --reason "..."`.
- **Out-of-scope records**: read `.out-of-scope/*.md` from both the repository (if present) and `<ws>/.out-of-scope/*.md`. Write new or updated `.out-of-scope/<concept>.md` files to `<ws>/.out-of-scope/<concept>.md` so the repository stays untouched.
- **Sync and git**: issue data lives in `<ws>/.beads/`. Do not run `bd dolt push`, `bd sync`, `git commit`, or `git push` unless the user explicitly asks.

## Triage queries and transitions

Every comment or issue posted during `/triage` must start with `> *This was generated by AI during triage.*`.

Query the three "Show what needs attention" buckets (oldest first) with:

1. **Unlabeled** (never triaged):
   `bd -C <ws> list --status open,in_progress,blocked,deferred --exclude-label needs-triage,needs-info,ready-for-agent,ready-for-human,wontfix,wayfinder:map,wayfinder:research,wayfinder:prototype,wayfinder:grilling,wayfinder:task --sort created --flat --json`
2. **`needs-triage`**:
   `bd -C <ws> list --status open,in_progress,blocked,deferred -l needs-triage --sort created --flat --json`
3. **`needs-info` with reporter activity since the last triage notes**:
   `bd -C <ws> list --status open,in_progress,blocked,deferred -l needs-info --sort created --flat --json`, then check `bd -C <ws> show <id> --include-comments --json` for comments posted after the latest `## Triage Notes` comment.

See `triage-labels.md` in `<ws>/docs/agents/triage-labels.md` for the category and state role mappings.

## When a skill says "publish to the issue tracker"

Create a Beads issue in `<ws>` with `bd -C <ws> create`.

- For `/to-spec`: `bd -C <ws> create "<spec title>" -t epic -s open -l ready-for-agent --body-file - <<'EOF' ... EOF`.
- For `/to-tickets`: create tickets in dependency order (blockers first) with `--silent` to capture each `<id>`, passing `--parent <spec-id> --no-inherit-labels -l ready-for-agent` when breaking down a parent spec and `--deps blocked-by:<blocker-id>` for native blocking edges. Omit the `## Blocked by` body section when blockers are wired as native dependencies.

## When a skill says "fetch the relevant ticket"

Run `bd -C <ws> show <id>` (or `bd -C <ws> show <id> --include-comments --json`).

## Wayfinding operations

Used by `/wayfinder`. The **map** is an `epic` issue in `<ws>` with **child** issues as tickets.

- **Map**: a single issue labelled `wayfinder:map`, holding the Notes / Decisions-so-far / Fog body: `bd -C <ws> create "<map title>" -t epic -l wayfinder:map --body-file -`. Update the map body with `bd -C <ws> update <map-id> --body-file -`.
- **Child ticket**: an issue linked to the map with `--parent <map-id> --no-inherit-labels` (giving hierarchical ids `<map-id>.1`, `<map-id>.2`, ...) and label `wayfinder:<type>` (`research`/`prototype`/`grilling`/`task`). Never apply a triage label to map tickets.
- **Blocking**: see **Blocking** under Conventions (`bd -C <ws> dep add <child-id> <blocker-id>`).
- **Frontier query**: `bd -C <ws> ready --parent <map-id> --unassigned --sort oldest --json`; first in map order wins.
- **Claim**: `bd -C <ws> update <ticket-id> --claim`, the session's first write.
- **Resolve**: `bd -C <ws> comments add <ticket-id> "<answer>"`, then `bd -C <ws> close <ticket-id> --reason "<one-line gist>"`, then update `<map-id>`'s body to append `- [<closed ticket title>](<ticket-id>): <one-line gist>` under `## Decisions so far`.
- **Rule out of scope**: `bd -C <ws> close <ticket-id> --force --reason "Out of scope: <why>"`, then add one line under `## Out of scope` in `<map-id>`'s body.
